## 🧠 What You Are Helping Me Build

**SalatTrack** is a Windows Forms desktop application built in **C# on .NET**, using **ADO.NET** and **Microsoft SQL Server**. It displays the 5 daily Islamic prayer times, sends alerts (toast/audio/silent), and logs prayer activity per user.

**This is a university assignment.** Code must be clean, well-commented, and demonstrate OOP principles clearly. **Keep it practical — no over-engineering.**

---

## 🏗️ Architecture — 3-Tier, Simple & Clear

```
Presentation Layer   →   SalatTrack.UI       (WinForms forms only)
Business Logic Layer →   SalatTrack.BLL      (calculations, alerts, Hijri logic)
Data Access Layer    →   SalatTrack.DAL      (ADO.NET only, no Entity Framework)
Shared Models        →   SalatTrack.Models   (POCO classes, no logic here)
```

**Rules to Follow:**

- UI never talks to DAL directly — always goes through BLL
- DAL never contains business logic — only SQL queries
- Models are plain classes with properties only — no methods with logic
- No Entity Framework, no Dapper, no ORM — **ADO.NET only**
- All SQL queries must use **parameterized queries** (no string concatenation)

## 🗄️ Database — Microsoft SQL Server

**Database name:** `SalatTrackDB`

### Tables

```sql
-- 1. Users
CREATE TABLE Users (
    UserID INT PRIMARY KEY IDENTITY,
    Username NVARCHAR(100) NOT NULL UNIQUE,
    PasswordHash NVARCHAR(256) NOT NULL,
    CityID INT,
    CreatedAt DATETIME DEFAULT GETDATE()
);

-- 2. Cities
CREATE TABLE Cities (
    CityID INT PRIMARY KEY IDENTITY,
    CityName NVARCHAR(100) NOT NULL,
    Latitude FLOAT NOT NULL,
    Longitude FLOAT NOT NULL,
    TimeZone NVARCHAR(50) NOT NULL
);

-- 3. PrayerTimes
CREATE TABLE PrayerTimes (
    PrayerTimeID INT PRIMARY KEY IDENTITY,
    CityID INT NOT NULL,
    Date DATE NOT NULL,
    Fajr TIME NOT NULL,
    Dhuhr TIME NOT NULL,
    Asr TIME NOT NULL,
    Maghrib TIME NOT NULL,
    Isha TIME NOT NULL,
    FOREIGN KEY (CityID) REFERENCES Cities(CityID)
);

-- 4. NotificationSettings
CREATE TABLE NotificationSettings (
    SettingID INT PRIMARY KEY IDENTITY,
    UserID INT NOT NULL,
    PrayerName NVARCHAR(20) NOT NULL,
    AlertType NVARCHAR(20) NOT NULL,  -- 'Toast', 'Audio', 'Silent'
    IsEnabled BIT NOT NULL DEFAULT 1,
    FOREIGN KEY (UserID) REFERENCES Users(UserID)
);

-- 5. Logs
CREATE TABLE Logs (
    LogID INT PRIMARY KEY IDENTITY,
    UserID INT NOT NULL,
    PrayerName NVARCHAR(20) NOT NULL,
    LoggedAt DATETIME NOT NULL DEFAULT GETDATE(),
    Status NVARCHAR(20) NOT NULL,  -- 'Prayed', 'Missed', 'Late'
    FOREIGN KEY (UserID) REFERENCES Users(UserID)
);
```

### Connection String (in App.config)

```xml
<connectionStrings>
  <add name="SalatTrackDB" 
       connectionString="Server=YOUR_SERVER;Database=SalatTrackDB;Integrated Security=True;" 
       providerName="System.Data.SqlClient" />
</connectionStrings>
```

## 🔌 Data Access Layer (SalatTrack.DAL)

### DBHelper.cs

- Static class that returns `SqlConnection` using the connection string from `App.config`
- All repositories use this to get connections
- Basic error handling for connection failures

### Repository Pattern (Simple & Practical)

**One interface per entity type:**

- `IUserRepository`
- `ICityRepository`
- `IPrayerTimeRepository`
- `INotificationSettingsRepository`
- `ILogRepository`

**Each repository implements these standard methods:**

```csharp
GetAll()              // Returns List<T>
GetById(int id)       // Returns T or null
Add(T entity)         // Insert
Update(T entity)      // Update
Delete(int id)        // Delete
```

**Special methods where needed:**

- `UserRepository.GetByUsername(string username)` → for login
- `PrayerTimeRepository.GetByCityAndDate(int cityId, DateTime date)` → for display
- `LogRepository.GetByUserAndDateRange(int userId, DateTime from, DateTime to)` → for filtering

**All queries use `SqlParameter` — ALWAYS.**

## 🔐 Security & Best Practices (University-Level)

| Item | Do | Don't |
|------|----|----|
| **Passwords** | Use **bcrypt** (NuGet: `BCrypt.Net-Next`) | SHA256 alone (it's weak without salt) |
| **SQL** | Parameterized queries: `SqlParameter` | String concatenation |
| **Connections** | Read from `App.config` | Hardcode strings in code |
| **Errors** | Catch & log (MessageBox is fine) | Ignore exceptions silently |
| **Forms** | Validate input (non-empty, length) | Accept anything |

---

## 🚫 Hard Rules — Never Break These

1. **No direct SQL string building** — always use `SqlParameter`
2. **No logic in Models** — they are data containers only
3. **No DAL calls from UI** — go through BLL always
4. **No Entity Framework** — ADO.NET only
5. **No inline connection strings** — always read from `App.config`
6. **Passwords must be hashed** — use bcrypt
